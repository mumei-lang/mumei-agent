## 2026-09-26: V1-B-2 follow-up 6 — intermediate Tier-3: one-level return taint, receiver mutexes, more sinks/sanitizers

- `agent/language_patterns.py` — intermediate expansion of the Tier-3-lite checks (still intra-file and warnings-only):
  - **Intra-file one-level taint propagation through function returns** (`taint_lite`): a first pass replays each function body's top-of-line assignments and return expressions — a function whose `return` is source-derived registers in a per-channel tainted-callee set, and calls to it taint the assignment target in every other body (`v := helper(r)` then `db.Query("…" + v)` flags). Exactly one level — `g → f → source` does not chain — because transitive closure needs the interprocedural call graph the analyzer deliberately lacks (see `docs/ROADMAP.md` analysis-infrastructure note).
  - **Mutex receiver association** (`go_shared_state`): method-body field writes are guarded by lock events on the *same* receiver — `other.mu.Lock()` no longer suppresses a write to `s.hits`, while bare `mu.Lock()` (package-level) still does.
  - **New sinks and sanitizers**: `exec.Command`/`exec.CommandContext` evaluate every untrusted argv element (Context variants skip `ctx`), `strconv.Itoa` clears the SQL channel, and `url.QueryEscape`/`url.PathEscape`/`template.HTMLEscapeString` clear the DOM channel.
- `docs/ROADMAP.md` — records the current analysis-infrastructure state (tree-sitter single-file + regex fallback + Python `ast`; no symbol/type/alias resolution, no call graph, no cross-file resolution) and the three future options — stack-graphs/SCIP, CodeQL/Semgrep integration, P17 bespoke — to revisit when needed.

## 2026-09-26: V1-B-2 follow-up 5 — `mumei:allow` opt-outs, composed Rust guards, trusted-atom surfacing

- `agent/language_patterns.py` — pattern findings now honor suppression markers in the file's own comment syntax: `# mumei:allow` (Python) / `// mumei:allow` (Rust/Go/TypeScript/Solidity) on the same line or the line immediately above suppresses the finding, and `#[allow(mumei::*)]` attribute lines do the same — plus, on a `fn` item, suppress every finding inside it (matching Rust attribute scoping). - Rust `unwrap`/`expect` guards: composed standard-library checks now count — `res.is_ok_and(..)`/`res.is_some_and(..)` guard the true path, `res.is_none_or(..)` guards the false/diverging path, and `res.ok().is_some()`/`res.err().is_none()`-style projection chains resolve through `_rust_check_polarity` (including inside `assert!` and the text fallback). `is_err_and`/`err().is_some()` deliberately stay non-guards: `true` proves `Err` and `false` is inconclusive. Directory audits aggregate them into `summary`/`report`/markdown output and add a medium-priority `next_steps` review item; advisory only — they never land in `errors` and never flip `success`.

## 2026-09-22: Layer B advisories — taint-lite sinks + Go shared state (Tier 3-lite)

- `agent/language_patterns.py` — two advisory groups (medium confidence, warnings-only):
  - **`taint_lite`** (Python/TypeScript/Go): request-derived values (`request.*`, `req.query/params/body`, `req.URL.Query()`, `c.Query()/Param()`, `input()`, `sys.argv`, `os.environ`, `location.*`, `localStorage`, …) tracked through plain assignments until they reach a sink — `execute`/`query`/`Query`/`Exec`/`raw`/`exec`/`Context` variants evaluate only the SQL-string argument (parameterized second-argument forms are the safe idiom), while `.innerHTML`/`outerHTML`/`document.write` flag taint anywhere in the statement. String literals reduce to their `{…}`/`${…}` interpolations before matching, so a `name` column in SQL text cannot alias a tainted `name` variable while `f"…{name}…"` still exposes it; assignments through `escape`/`shlex.quote`/`DOMPurify.sanitize`/`strconv.Atoi`/… clear the taint.
  - **`go_shared_state`**: only active in files that declare `sync.(RW)Mutex` fields (the locking discipline already exists) — a function writing a package-level `var` or a method writing `receiver.field` without a `.Lock()` before the write flags once per function. Atomic wrappers (`atomic.Add*` on `&var`), writes to the mutex field itself, read-only functions, and mutex-free files are skipped.
- Known limits (advisory-lite scope): taint sources/sinks are a fixed common set; Go regex fallback misses methods with receivers (tree-sitter path covers them); the lock check is presence-based, not scope/aliasing-aware.

## 2026-09-22: Layer B advisories — new language_patterns (Tier 2)

- `agent/language_patterns.py` — five new advisory groups (all `confidence="medium"`, warnings-only; advisory findings cannot invert `success`):
  - **Solidity** (inside `solidity_pattern`): weak randomness — `blockhash(...)` or `block.timestamp`/`number`/`prevrandao`/`difficulty`/`coinbase` feeding a `keccak256` hash or a `%` draw; missing zero-address guard — a `public`/`external` function storing an `address`/`address payable` parameter into state with no `address(0)` check anywhere in the body.
  - **Rust** (`rust_escape_hatch`): `unsafe {}` blocks, `mem::forget`, `mem::transmute` — points where the borrow/type guarantees are suspended and the safety invariant is manual.
  - **Python** (`python_dangerous_call`, AST-based): `eval`/`exec`, `pickle.load`/`loads`, `marshal.load`/`loads`, `os.system`/`os.popen`, `subprocess.*` with `shell=True` (or `getoutput`), `yaml.load` without a `Loader=` argument.
  - **Python** (`python_mutation_during_iteration`): mutating the iterated collection inside its own `for` — `items.remove(x)`, `del d[k]`, `d[k] = v` — which skips elements (lists) or raises `RuntimeError` (dicts/sets). Iterating a copy (`for x in list(items)`) is recognised as safe.
  - **TypeScript** (`typescript_safety`; JavaScript aliases to it): non-null assertions `x!`/`f()!`/`a[i]!` (excluding `!=`/`!==`), `JSON.parse` with no `try`/`catch` in the body, `eval(`, `.innerHTML =` assignments, and mutating the `for … of` array (push/splice/subscript-write) inside the loop.

## 2026-09-22: Layer B checks — shift bounds + sentinel -1/undefined + Go ignored errors

- `agent/strategies/foreign_code_strategy_helpers.py` — three more check classes on top of the Tier1-A body-level scan:
  - **Shift-amount bounds** (`_shift_amount_issues`): `x << n`/`x >> n`/`<<=`/`>>=` flag when `n` isn't provably below the base's declared bit width — a Rust debug panic, a silent 5-bit mask in TypeScript/JavaScript (all shifts treated as 32-bit), a defined-but-likely-wrong result in Go/Solidity. Literal counts `>= width` always flag; `n & (W-1)`, `n % W`, and `n < W`/`n <= W-1` comparisons *before* the shift suppress (`_shift_amount_guarded` is position-aware like `_subtraction_guarded`: a `||`/`:` between the guard and the shift means it doesn't guard). Emits `n < W` when `n` is a declared param. Python is skipped (arbitrary precision).
  - **Sentinel -1/`undefined` use** (`_sentinel_index_issues`, body-level): `i = s.indexOf(x)`/`strings.Index(...)`/`s.find(x)` followed by `…[i]` without a numeric comparison on `i`, and `el = arr.find(p)` followed by `el.`/`el[`/arithmetic without an `undefined`/`null`/`if (el)`/`!el` check — `el?.` counts as safe. Direct `arr[s.indexOf(x)]` inline indexing flags unconditionally. Guards must appear between the assignment and the use. Medium-confidence advisory (locals can't carry caller contracts).
  - **Go ignored error returns** (`_go_ignored_error_issues`): `x, _ := f()` discarding the trailing value, and bare `f(...)`/`go f(...)` statements, flag when `f`'s same-file signature ends in `error` — built from the tree-sitter `functions` or regex `go_decls` declarations. `defer f()` is skipped (idiom). Medium-confidence.
- Both Go detection paths (tree-sitter and regex fallback) run the sentinel/ignored-error scans per body; TypeScript sentinel runs inside `_detect_block_safety_issues`; Python `s.find` sentinel runs per `ast.FunctionDef` via `ast.get_source_segment`.
- Regression gate: `uv run pytest tests/test_foreign_code_tier1b.py -q` (38 cases); full suite green (2502 passed). Known limits: guard regexes are textual (a `case -1:` switch arm is not a guard); `x, _, _ := f()`-style multi-discards key on the last position only; sentinel checks key on the common `indexOf`/`find`/`strings.Index`/`str.find` families.

## 2026-09-22: Layer B checks — narrowing casts + unsigned subtraction underflow

- `agent/strategies/foreign_code_strategy_helpers.py` — two new contract-generating checks appended at both `_issues_for_expression` return paths (tree-sitter and regex fallback), so they apply uniformly to Solidity, Rust, and Go:
  - **Narrowing casts** (`_narrowing_cast_issues`): Rust `x as uN`, Go `uN(x)`/`iN(x)`/`byte(rune)`, and Solidity `uintN(x)`/`intN(x)` conversions flag when the operand's declared type is provably wider or a sign flip makes half the source range unrepresentable — `u64 → u8` emits `x <= 255`, `i64 → u64` emits only `x >= 0` (the upper bound is vacuous and suppressed). Constants already in range and same-sign widening casts are skipped. Solidity's ≥0.8 default checks cover arithmetic operators only — explicit conversion functions truncate on every compiler version, so casts flag under ≥0.8 too.
  - **Unsigned subtraction underflow** (`_unsigned_subtraction_issues`): `a - b` and `a -= b` between provably unsigned operands (declared param type or `unsigned_locals`) flag unless a constant/`_subtraction_guarded` ordering proves `a >= b`. The guard is position-aware: a comparison in a ternary false branch suppresses the negated direction (`a >= b ? a - b : b - a`), while `a <= b` never suppresses — it proves the opposite. Emits `a >= b` as the required contract with a Z3 counterexample.
- `_detect_block_safety_issues` now threads `per_function_param_types` (mumei-normalized) and `per_function_raw_param_types` into both paths; `_solidity_params` gains `normalize=False` so Solidity keeps its declared `uint256`-style widths for the width lookup instead of collapsing to `u64`.
- Noise control: casts flag only when the operand's declared type is known (param/raw types) — locals can't carry contracts so unknown-typed expressions stay silent; unsigned subtraction only flags when *both* operands are proven unsigned. Under Solidity ≥0.8 the subtraction check is scoped to `unchecked { … }` regions (arithmetic reverts outside them); a param name redeclared as a typed local is treated as a shadowed binding. `_detect_block_safety_issues` and both Go paths also run the checks over the whole body so non-return statements are covered, reconciled against the per-expression results so enclosing `if` guards still suppress. Known limit: the ternary guard reads a single expression level.
- Regression gate: `uv run pytest tests/test_foreign_code_casts.py -q` (42 cases: Rust/Go/Solidity flag + skip + guard + constant + shadowing + unchecked-scope); full suite green.

## 2026-09-22: V1-B-2 follow-up 4 — Rust conditional repairs count as guards

- `agent/language_patterns.py` — Rust: an `if` whose empty-variant branch unconditionally repairs the receiver now guards a later `unwrap()`/`expect()` — `if res.is_none() { res = Some(0) } res.unwrap()` no longer flags. `_rust_if_conditional_repair` pairs the existing condition polarity analysis with per-branch repair-effect scans (`_rust_block_repair_effect`): the empty path must end `repaired`, the value path must not end `invalidated`. Repairs through `&mut` aliases (`*p = Some(..)`) and insert-style methods (`res.insert(..)`) inside branches count; `else`/`else if` chains are followed, and writes under a nested condition still flag. A `let` inside a branch only shadows — it is never a repair — and a `let-else` whose diverging arm also repairs now counts as a guard too. Guard recognition inside the write-scan also uses it, so `res = None; if res.is_none() { res = Some(0) } res.unwrap()` stays clean while a conditional repair that only *might* run keeps flagging.
- Remaining limits (documented, deliberately out of scope): cross-file/import resolution, custom guard functions, and `#[allow]`-style opt-outs.

## 2026-09-21: V1-B-2 follow-up — tree-sitter scoped detection + advisory confidence

- `agent/language_patterns.py` detectors now receive a shared `PatternContext` (`detect(source, ctx)`) carrying the whole-file tree-sitter parse, built once per `language_pattern_issues` call via the new public `tree_sitter_extract.parse`. The Rust `unwrap`/`expect` detector is scope-aware: a guard only suppresses when it dominates the call — enclosing `if`/`while`/`let`-condition consequence or the `else` of a negative check, `match` value arms on the same receiver, short-circuit `&&`/`||` right operands, and preceding diverging guards in an enclosing block (`let-else`, `if … { return }`, `assert!(recv.is_ok())`, `recv?`, fully-guarded `match`). Guards in sibling branches, after the call, on a different receiver, or outside a `fn`/closure/`async` boundary no longer suppress the finding; `for v in res` (or `&res`/`res.iter()`) over an Option/Result counts as a guard since the body runs only for the value variant. The TypeScript floating-promise detector collects `async` names from syntax (`async` tokens on declarations/methods/bound arrows, including `{ send: async x => x }` pairs and `x = async …` assignments) and decides handled-ness from the call's syntactic context (await/return/throw/yield, declarator/assignment, arguments incl. `Promise.all([…])`, `.then`/`.catch`/`.finally` chains, expression-bodied arrows) instead of an 80-char prefix regex. JSX attribute/child expressions (`onClick={send(1)}`) count as floating — the consumer never awaits — and `obj['send'](…)` resolves the callee through the string index. When the grammar is unavailable both fall back to the previous text scans.
- `ForeignSafetyIssue` gains `confidence: ConfidenceLevel` (`"high"`/`"medium"`/`"low"`, default `"high"`): tree-sitter/Python-`ast` findings and counterexample-backed findings are `"high"`; pure text heuristics (Go defer, Solidity patterns, the access-control advisory, and both regex fallbacks) report `"medium"`. `CrossValidationIssue` gains a matching `confidence` field (`""` default) wired through `_language_advisory_issues` — warnings-only design unchanged (severity still `error`-iff-counterexample).
- Regression gate: `uv run pytest tests/test_language_patterns.py -q` (112 cases incl. scoped-guard, fallback, and confidence checks); full suite green.
- Remaining limits: the TS await set still only covers same-file `async` names (calls through variables/imports/aliased members are unresolved); Rust guard recognition covers the common `Option`/`Result` idioms (custom guard fns and `#[allow]`-style opt-outs are not read).
